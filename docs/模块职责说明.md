# Shellcontrol / Easycontrolfork 模块职责说明

## 1. 项目总体架构

本项目是一个**双端协作的 Android 远控系统**，由同一仓库内两个 Gradle 模块组成：

- `app`：控制端应用（UI、设备管理、ADB 连接、流媒体解码与控制指令发送）。
- `server`：被控端运行的服务端（视频/音频采集编码、控制事件执行、系统服务封装）。

在构建链路上，`server` 模块会构建为 APK，并在构建任务中重命名复制为 `easycontrolfork_server.jar`，再由 `app` 通过 ADB 推送到目标设备后用 `app_process` 启动。该模式使控制端与被控端协议保持同仓协同演进。

---

## 2. Gradle 模块职责

## 2.1 `:app` 模块（控制端）

### 核心职责
- 提供设备列表与配置界面（添加、编辑、连接策略）。
- 建立 ADB 连接（USB / TCP）并分发命令。
- 负责控制会话生命周期：连接、重连、断开收尾。
- 接收并解码远端音视频流，驱动悬浮窗 / 小窗 / 全屏显示。
- 将触控、按键、剪贴板、分辨率等控制动作编码并发送给 `server`。

### 关键分层与包职责
- `app` 根包 Activity 层：页面入口与设置流程
  - `MainActivity`：主入口、设备列表挂载、广播注册、自启动连接。
  - `DeviceDetailActivity` / `SetActivity` / `IpActivity` / `UsbActivity` / `AdbKeyActivity`：设备参数、全局设置、网络与密钥等辅助流程。
- `app/entity`：数据模型与全局上下文
  - `Device` / `Setting`：设备连接参数与行为策略。
  - `AppData`：全局单例上下文（数据库、系统服务、ADB 密钥等）。
- `app/helper`：UI 与基础设施工具
  - `DbHelper`：设备配置持久化（SQLite）。
  - `DeviceListAdapter`：设备列表展示与交互桥接。
  - `ViewTools` / `PublicTools` / `MyBroadcastReceiver`：通用 UI、工具与系统广播处理。
- `app/adb`：ADB 协议与通道抽象
  - `Adb`、`AdbProtocol`、`TcpChannel`、`UsbChannel`、`AdbKeyPair`：建立握手、命令执行、文件推送。
- `app/client`：会话编排核心
  - `Client`：会话总控（连接、关闭、重连策略、组件装配）。
  - `client/tools`：
    - `AdbTools`：ADB 连接缓存、命令执行与文件推送统一入口。
    - `ClientStream`：与远端 server 的主通道/视频通道通信。
    - `ClientController`：控制动作调度。
    - `ControlPacket`：控制指令打包。
    - `ClientPlayer`：音视频消费调度。
  - `client/decode`：`VideoDecode` / `AudioDecode` 解码。
  - `client/view`：`SmallView` / `MiniView` / `FullActivity` 等多形态展示容器。
- `app/buffer`：流式缓冲结构封装，用于提升实时传输稳定性。

## 2.2 `:server` 模块（被控端服务）

### 核心职责
- 初始化 Android 系统服务访问层（显示、输入、剪贴板、窗口等）。
- 建立双 Socket 通道（控制主通道 + 视频通道）。
- 从设备侧采集并编码视频/音频，向控制端推流。
- 接收控制指令并执行（触摸、按键、电源、旋转、分辨率、剪贴板等）。
- 在会话结束时进行资源回收（编码器、分辨率、超时恢复等）。

### 关键分层与包职责
- `server/Server`：入口与线程编排（参数解析、连接建立、收发循环、生命周期管理）。
- `server/entity`：设备状态与运行参数
  - `Options`：启动参数解析。
  - `Device`：设备状态、分辨率/电源相关控制能力。
  - `DisplayInfo` / `Pointer` / `PointersState`：显示与输入状态对象。
- `server/helper`：编解码与协议处理
  - `VideoEncode` / `AudioEncode` / `AudioCapture`：采集与编码管线。
  - `ControlPacket`：控制事件解析与执行。
  - `EncodecTools` / `FakeContext`：编码和上下文兼容辅助。
- `server/wrappers`：系统隐藏能力封装
  - `SurfaceControl` / `WindowManager` / `DisplayManager` / `InputManager` / `ClipboardManager`。

## 3. 核心运行链路（职责视角）

1. 控制端 `app` 启动后，`MainActivity` 初始化 `AppData`，加载数据库中的设备配置并展示。
2. 用户发起连接后，`Client` 负责会话创建；`AdbTools` 提供 ADB 连接与命令执行。
3. 控制端通过 ADB 将 `easycontrolfork_server.jar` 推送并在被控端启动 `server.Server`。
4. `server` 建立 Socket 后进入多线程循环：视频输出、音频输入/输出、控制输入。
5. 控制端 `ClientStream` 接收流，`ClientPlayer` + `decode` 层解码渲染到不同视图容器。
6. UI 操作经 `ClientController` → `ControlPacket` 编码后发送，`server.helper.ControlPacket` 执行到系统层。
7. 连接关闭时，`Client` 进行本地策略收尾（锁屏/亮屏/重连），`server` 释放编码器与系统设置。

---

## 4. 模块边界与依赖原则

- `app` 与 `server` 通过**协议**和 `jar` 投送集成，避免运行时强耦合。
- `app` 内部采用“UI → 会话编排 → 协议/ADB → 传输/解码”分层，降低页面逻辑与协议实现耦合度。
- `server` 内部采用“入口编排 → 能力封装（wrappers）→ 编码/控制执行（helper）→ 状态模型（entity）”结构，便于针对不同 Android 版本适配。

## 5. 后续演进建议（文档用途）

- 建议新增 `docs/protocol.md`，统一维护主通道/视频通道数据帧格式与版本兼容策略。
- 建议把 `app/client/tools` 中的连接管理、控制指令、媒体播放进一步接口化，提升可测性。
- 建议在 `server/wrappers` 增加 Android API level 兼容矩阵，降低系统差异导致的问题定位成本。
